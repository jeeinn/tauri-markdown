# 多标签页编辑器 - 需求文档

## 1. 概述

### 1.1 项目背景
Tauri Markdown 是一个基于 Tauri + Vue 3 + Vditor 的桌面 Markdown 编辑器，当前仅支持单文档编辑模式。

### 1.2 需求目标
为应用添加多标签页文档编辑功能，每个标签页可以独立编辑不同的 Markdown 文件，实现类似 VS Code、Typora 等现代编辑器的多标签体验。

### 1.3 技术方案
采用 Vue 3 组件 + KeepAlive 的方案：
- 在 App.vue 中维护 Tabs 数组状态
- 每个 Tab 对应一个 MyVditor 组件实例
- 使用 `<KeepAlive>` 缓存非活跃 Tab 的组件状态
- 动态生成 Vditor 实例的 DOM id 实现实例隔离

## 3. 功能规格

### 3.1 标签页管理

#### 3.1.1 标签页结构
```
Tab = {
  id: string,               // 唯一标识（UUID）
  title: string,            // 标签标题（文件名）
  filePath: string | null,  // 文件路径（null 表示未保存的新文档）
  contentModified: boolean, // 是否有未保存修改
  active: boolean,          // 是否为当前活跃标签页
  scrollPosition: number,   // 滚动位置（0-1 百分比）
  editMode: 'ir' | 'sv' | 'wysiwyg', // 编辑模式
 VDitorState: any          // Vditor 状态快照（可选）
}
```

#### 3.1.2 标签栏 UI
- 顶部菜单栏下方添加标签栏组件
- 支持以下操作：
  - 点击标签切换
  - 点击 "×" 关闭标签页
  - 标签显示文件名，有修改时添加 "●" 标记
  - 未保存文档显示 "未命名●"
  - 支持右键菜单（关闭其他、关闭全部、复制路径等）

#### 3.1.3 标签页关闭行为
| 操作 | 未保存修改 | 行为 |
|------|-----------|------|
| 点击 "×" | 有 | 显示三按钮对话框（保存/不保存/取消） |
| 点击 "×" | 无 | 直接关闭 |
| App 关闭 | 有任意未保存 | 显示汇总对话框，用户可选择全部保存/丢弃/取消 |

### 3.2 新建标签页

#### 3.2.1 触发方式
- 菜单：文件 → 新建
- 快捷键：Ctrl/Cmd + T
- 标签栏 "+" 按钮

#### 3.2.2 行为
1. 检查当前活跃标签页是否有未保存修改，如有则提示
2. 创建新 Tab 对象（filePath=null, contentModified=false）
3. 插入 Tabs 数组并设为活跃
4. 初始化 MyVditor 组件实例
5. 调用 `MyVditor.newFile()` 清空内容

### 3.3 打开文件到标签页

#### 3.3.1 触发方式
- 菜单：文件 → 打开
- 快捷键：Ctrl/Cmd + O
- 拖拽文件到标签栏
- 标签栏拖拽文件

#### 3.3.2 行为
1. 检查当前标签页是否有未保存修改
2. 弹出文件选择对话框（或使用拖拽文件路径）
3. 如果文件已打开，在对应标签页加载
4. 否则创建新标签页并加载文件
5. 恢复该文件的滚动位置和编辑模式

### 3.4 保存操作

#### 3.4.1 保存当前标签页
- 菜单：文件 → 保存
- 快捷键：Ctrl/Cmd + S

#### 3.4.2 行为
1. 如果 filePath 存在，直接写入
2. 如果 filePath 为 null，弹出保存对话框
3. 保存成功后更新 Tab 状态

### 3.5 滚动位置记忆

#### 3.5.1 每个文件的滚动位置独立保存
- 使用 `store.js` 的 `saveScrollPosition(filePath, percentage)`
- Tab 切换时恢复对应文件的滚动位置
- 支持 `scrollRemember` 开关控制

### 3.6 持久化存储

#### 3.6.1 保存项
| Key | Value | 说明 |
|-----|-------|------|
| `tabs` | Tab[] | 所有标签页的状态数组 |
| `activeTabId` | string | 当前活跃标签页 ID |
| `lastOpenTabs` | string[] | 上次打开的文件路径列表 |

#### 3.6.2 恢复逻辑
1. App 启动时从 Store 读取 tabs
2. 依次恢复每个 Tab（检查文件是否存在）
3. 设置 activeTabId
4. 跳过不存在的文件，显示通知

## 4. 非功能需求

### 4.1 性能
- 标签页数量无硬限制，但建议不超过 20 个
- 切换响应时间 < 200ms
- 内存占用：每个 Tab 约 15-30MB（Vditor 实例）

### 4.2 兼容性
- 支持 Windows/macOS/Linux
- 支持所有现有功能（主题、Zen 模式、图床等）

### 4.3 国际化
- 所有 UI 文本支持 4 种语言（zh_CN/en_US/ja_JP/ko_KR）
- 新增翻译键见附录 A

### 4.4 可访问性
- 标签栏支持键盘导航（Tab 切换、方向键移动）
- 为标签页添加 aria-label

## 5. 依赖项

### 5.1 外部依赖
- `uuid`: 生成唯一 Tab ID
- `element-plus`: 标签栏 UI 组件

### 5.2 内部依赖
- `MyVditor.vue`: 编辑器组件（需支持动态 id）
- `store.js`: 持久化存储
- `scroll-memory.js`: 滚动位置管理
- `unsaved-check.js`: 未保存修改检查
- `i18n-helper.js`: 国际化

---

## 6. 设计约束

### 6.1 技术限制
- Vditor 实例不能共享 DOM id，必须动态生成
- KeepAlive 不支持直接 v-for，需要配合动态组件
- Tauri 窗口不能嵌入多个 WebView，必须使用前端 Tab 实现

### 6.2 架构约束
- 保持现有 App.vue 结构最小化改动
- MyVditor 组件需支持通过 prop 传入动态 id
- 不改变现有状态管理逻辑，仅扩展
